# AGENTS.md

TPLive — Flutter bus tracker for TransPadang (Padang). See `README.md` for full detail.

## Repo layout
- This directory is the git repo root. Run **all** Flutter/git commands from here.
- Sibling folders at `K:\REP` (`padang/`, `_backup_transpadang/`, `_assets_logo_backup_*/`, root `*.apk`) are outside this repo — leave them alone.

## Toolchain (hard constraint)
- Flutter **3.19.6** / Dart **3.3.4**. Newer APIs break the build:
  - ❌ `Color.withValues`, `surfaceContainer*`, `WidgetState*` / `WidgetStatePropertyAll`, `CardThemeData` / `DialogThemeData`, `FadeForwardsPageTransitionsBuilder`.
  - ✅ Keep `withOpacity`, `surfaceVariant`, `MaterialStatePropertyAll`, `CardTheme`, `DialogTheme`.
- `withOpacity` is intentionally used here (not deprecated on 3.19). Do not "modernize" it.

## Commands
- Setup: `flutter pub get`
- Analyze: `flutter analyze` — baseline is **0 issues**. Berkas `lib/l10n/app_localizations*.dart` dikecualikan karena generated. Any new issue is a regression.
- Test: `flutter test` (214 tests). Single file: `flutter test test/home_tabs_test.dart`.
- Run: `flutter run -d <id>` (physical Android device, e.g. `a0d334d3` / model `2203129G`). `flutter run` stays attached; it does not exit.
- Localization: edit `lib/l10n/app_id.arb` (**template**) **and** `lib/l10n/app_en.arb`, then `flutter gen-l10n`. Generated `lib/l10n/app_localizations*.dart` are **tracked** — commit them too.
- Release: `scripts/build_release.ps1` (requires `dart_defines.json`, copy from `dart_defines.example.json`; that file is tracked and holds `MAPBOX_TOKEN`). Empty token → geocoding falls back to Nominatim.
- Assets: `scripts/generate_logo_assets.ps1`, then `dart run flutter_launcher_icons` / `dart run flutter_native_splash:create`. **Splash caveat:** `values-v31/styles.xml` & `values-night-v31/styles.xml` carry custom edge-to-edge items (`windowDrawsSystemBarBackgrounds`, `statusBarColor`, `navigationBarColor`, `windowLayoutInDisplayCutoutMode`) that `flutter_native_splash:create` would **overwrite**. Also the source logo (`splash_a12.png`/`splash_pre12.png`) has an **opaque white background**, so a dark splash cannot show the logo without a transparent/dark `image_dark` asset. Dark mode therefore uses a **solid surface-colored splash with no logo** (see `values-night-v31/styles.xml` + `drawable-night/launch_background.xml`). Do not re-run `:create` unless you first fix both.
- Stop coordinates: `python scripts/fix_halte_coords.py --corridor K3 [--apply] [--report docs/halte_k3_audit.md]` audits/repairs `assets/halte.json` (detects collapsed blocks, matches OSM `highway=bus_stop` nodes in `scripts/data/osm_halte_padang.json`, applies the hand-checked `scripts/data/halte_overrides.json`). **K3 is locked out of this script** (`MANUAL_CORRIDORS`): its stops are hand-surveyed — edit `scripts/data/manual/K3_pulang.txt` / `K3_pergi.txt` and import with `python scripts/import_halte_txt.py --corridor K3 --dir <pergi|pulang> --file <txt> [--write]` (dry-run prints gaps and offsets to `assets/routes/K3.geojson`; `--write` regenerates ids). `--force` overrides the lock. `assets/corridor_routes.json` for K3 is a copy of `assets/routes/K3.geojson` so audit/map tooling sees the same geometry. `python scripts/build_halte_map.py` renders the before/after map to `docs/halte_k3_map.html` (pairs stops by name, marks added/removed).
- Stop/route audit (dev-only, never edits assets): `dart run scripts/audit_halte.dart` → `tools/halte_audit.csv` (duplicate names, same-name pairs >150 m, backward jumps, zero gaps, route-length vs stop-gap ratio, stops outside the Padang bbox). `dart run scripts/fetch_osm_stops.dart` → `tools/halte_candidates.csv` + `tools/osm_stops.json` (Overpass, 3 mirrors with retry; OSM has only ~19 named stops in the Padang bbox, so it validates but cannot replace `halte.json`). `dart run scripts/clean_corridor_routes.dart [--write]` re-chains each corridor polyline as the shortest sub-path between consecutive stops (kills the "spaghetti" loops that make K4 draw 58 km); preview by default, and it refuses a direction when stop order/offsets would get worse.
- Demo/mock data (opt-in, zero effect on normal builds): `flutter run --dart-define=MOCK_BUS=true [--dart-define=MOCK_LOCATION=-0.9478,100.3543]`. `MockBusSource` (`features/tracking/data/mock_bus_source.dart`) drives buses along each corridor's real stop sequence, refreshing every 2 s with a fresh `lastUpdate`; `mockBusEnabledProvider` swaps it in `busSourceProvider` and makes `isOutsideHoursProvider` always false (so demos work at night); `mockLocationProvider` replaces GPS. Both providers are overridable, so tests never depend on the compile-time flag. Caveat: "Ikuti bus" still starts the native `FollowService`, which talks to the real server, so follow notifications do not fire for mock buses.

## Architecture
- Entry `lib/main.dart`: `ProviderContainer` + `DynamicColorBuilder` + `MaterialApp(builder: RootOverlay)`.
- `lib/core/`: `config.dart` (all constants/URLs/hours), `settings.dart` (prefs), `follow_service.dart` (MethodChannel), `app_navigator.dart`, `theme/`, `ui/`.
- Features: `lib/features/<tracking|trip|settings>/{data,domain,presentation}`. There is **no** Dart splash screen: the app starts straight on `HomeScreen`. The native `LaunchTheme` splash already covers the engine-start gap, `main()` loads prefs/theme/locale before `runApp`, and the home screen shows its own `LoadingStateView` while GPS connects — an in-app splash only added ~1.8 s of the same logo shown twice. Do not reintroduce one without a real load to hide. **Dark-mode native splash:** `windowSplashScreenBackground` is `#201A17` (matches `ColorScheme.fromSeed` dark `surface`, probed from `buildAppTheme(Brightness.dark)`) and intentionally has **no logo** — the white-bg logo asset would render a white box on dark. Light mode keeps the white bg + logo.
- Theming is centralized in `lib/core/theme/app_theme.dart` (seed `#F47F38`). Add component styles there, not per-widget.
- Animation durations/curves live in `lib/core/theme/app_motion.dart` (`AppMotion.*`). Do not hardcode `Duration`/`Curve` in screens.
- Reuse the shared kit: `lib/core/ui/state_views.dart`, `lib/core/ui/fade_through_route.dart`, `lib/core/ui/constrained_content.dart` (centers + caps content width, already used by home/trip/settings),   `features/tracking/presentation/widgets/corridor_badge.dart`, `.../corridor_selector.dart` (`CorridorIconButton`/`CorridorPalette` — round corridor selector used by home **and** the map), `.../location_error_view.dart` (GPS permission/service errors, shared by home and trip). Do not re-add per-screen copies.
- Map (live): `flutter_map` 6.1.0 (pinned — 6.2.1 needs `meta ^1.12` and breaks version solving on Flutter 3.19). Tiles are **Mapbox raster first, OSM fallback**: `mapTileSourceProvider(isDarkTheme)` resolves `AppSettings.mapMode` (`MapMode.theme/light/dark/satellite` in `core/map_mode.dart`, persisted as `settings.map_mode`) against the current theme brightness and returns `(urlTemplate, fromMapbox)`. Mapbox styles live in `AppConfig.mapboxTileUrl(style)` (`streets-v12`, `dark-v11`, `satellite-streets-v12`); when the token is empty everything falls back to `AppConfig.osmTileUrl` and dark mode is faked with a `ColorFiltered` matrix on the OSM layer. Attribution must follow the source: `l10n.mapAttributionMapbox` ("© Mapbox © OpenStreetMap") vs `l10n.mapAttribution`. Screen `features/tracking/presentation/widgets/map/map_screen.dart` (`AppBar` `PopupMenuButton<MapMode>` = style picker), view `.../bus_map_view.dart`, pure marker logic `.../domain/map_marker.dart`. **All map controls live bottom-right inside `BusMapView`**: the "focus bus" FAB (only while a bus is selected, calls the private `_focusSelectedBus()`) sits directly above the "my location" FAB — do not float it in a corner of `MapScreen` again. `map_stop_sheet.dart` is the tap-a-halte sheet: keep its glyph `Icons.departure_board` (a bus icon was wrong for a stop) and its `maxWidth: 560`. The corridor filter is a **collapsible capsule over the map**, not an `AppBar.bottom` band: collapsed (default) it is a single 48 dp circular button at the top-left holding **only** the chevron (no colour dot, no corridor label — the active corridor is already readable from the route colour on the map; the corridor name survives for screen readers as `Semantics.value`); tapping it expands the same capsule to full width with the "Semua" chip + corridor circles (`mapFilterExpandedProvider`). Its chevron is **horizontal** (`Icons.chevron_right` in an `AnimatedRotation`, `turns: 0` collapsed / `0.5` expanded → points left), because the capsule grows sideways; the vertical `expand_more`/`expand_less` pair promised a downward motion that never happens. `BusMapView` collapses it again on any gesture pan (`MapOptions.onPositionChanged` → `hasGesture`) and on map tap, so the user never has to hunt for a close button; programmatic camera moves (`hasGesture == false`) leave it alone. `MapScreen.filterToggleKey` is the stable key for tests. `_topOverlayOffset` (64) positions the outside-hours banner and the focus FAB just below it; the horizontal `ListView` intentionally lets the last circle clip at the edge as a scroll affordance. Tile source is injected via `tileProviderProvider` (fake in tests) and the Mapbox token via `mapboxTokenProvider` (tests override it with `''` / `'pk.test'`). Buses are filtered by `selectedCorridorProvider`. The selected-bus bottom card reuses `PinnedBusCardBody`/`PinnedBusCardFooter` (shared with the pinned overlay) and has a `FollowBusButton`; while a bus is selected the map sets `mapBusSelectedProvider` so `PinnedBusOverlay` hides (no stacked cards). `speed_dial.dart` (`BusSpeedDial`) is the shared speed dial. The map reads `mapUserLocationProvider` (high accuracy, `autoDispose`) — the rest of the app uses the battery-cheap `userLocationProvider`.
- Floating pinned card: `PinnedBusOverlay` is mounted in `MaterialApp.builder`, i.e. **above** the Navigator, so it also paints over modal bottom sheets. It returns `SizedBox.shrink()` when `mapBusSelectedProvider` is true (the map's own bus card is showing) and when `pinnedDetailOpenProvider` is true (a bus timeline sheet is open — that sheet already shows badge/number/current+next halte/progress, so the card would only cover the halte list). Otherwise it rests collapsed and expands on tap; tapping the expanded card opens the timeline. Never reintroduce a "visible but `onTap: null`" state — that is a dead element. Three live actions in the expanded card, top-right: chevron (`Icons.expand_more`, `onCollapse`) → back to mini **without unpinning**, and X (`onClose`) → unpin. Both are `_CardIconButton`s (48 dp) laid out as an overlay so the header height is untouched; `_Header.trailingSpace` reserves 44 dp per button.
- Arrival ETA to the user: `domain/user_arrival.dart` (`UserArrival.estimate`) turns the bus position + user GPS into `distanceKm` / `etaMinutes` / `isHere`. It is **straight-line distance ÷ current speed** (`geo.estimateEtaMinutes`, falls back to `AppConfig.defaultSpeedKmh`), the same approximation used for "halte berikutnya" — never present it as a road-network ETA. It is **always shown** when a location exists: a "bus is moving away" gate (heading vs bearing) was tried and removed because server heading + differing GPS accuracy between the map (precise) and the overlay (medium) made the estimate disappear/reappear. Show the distance next to the minutes so a growing distance explains itself. The overlay reads `userLocationProvider` **after** its early returns so GPS is not subscribed when nothing is pinned. Surfaced twice: a `≈ N mnt` chip in `_CompactHeader` (mini state) and a full line in `PinnedBusCardFooter` (shared with the map's bus card). Keep both in sync when changing copy; l10n keys are `arrivalEta`, `arrivalEtaShort`, `arrivalNear`, `arrivalHereShort`.
- Battery/lifecycle: `userLocationProvider` is `LocationAccuracy.medium` + `distanceFilter: 10`; `preciseLocationProvider` (`autoDispose`, `high`) only lives while the map is open. `main.dart` installs `_AppLifecycleObserver`, which writes `appPausedProvider`; `liveUpdatesAllowedProvider` then closes the bus WebSocket in the background (`busesProvider` → empty, `connectionStatusProvider` → `connecting`) **except** while following a bus, because arrival notifications must keep running. Keep this gate in mind when adding new socket consumers.
- Android native: `android/app/src/main/kotlin/id/dwiky/transpadang_live/` (`MainActivity.kt`, `FollowService.kt`, `HalteMath.kt`). MethodChannel `id.dwiky.transpadang_live/follow`. `HalteMath.kt` is a minimal port of `halte_tracker.dart`/`geo_utils.dart` for `FollowService` only — don't re-add unused geometry helpers. Notification accent color comes from Dart (`startFollow` extra `color`); the corridor-color table lives only in `format.dart`. Notification copy is localized in Dart and sent as the `labels` JSON extra (keep native fallbacks for older sessions). `applicationId`/`namespace` = `id.dwiky.transpadang_live`; `compileSdk 36`, `minSdk 21`.

## Domain quirks (already normalized — do not "fix")
- Server **swaps** `latitude`/`longitude`; normalized in `Bus.fromJson`.
- `last_update` is WIB (UTC+7), stored as UTC; buses older than 5 min are hidden.
- Operating hours 06:00–19:00 WIB (`AppConfig`); outside hours shows purple `0xFF7B1FA2`.
- Stop data is bundled (`assets/halte.json`, corridors K1–K6). No REST dependency.

## Gotchas that break things
- **`Tooltip` crashes outside the Navigator `Overlay`.** `PinnedBusOverlay` is mounted in `MaterialApp.builder`, outside the Navigator's `Overlay`, so `Tooltip` throws "No Overlay widget found". Use `Semantics(label: ...)` there instead (see `floating_pinned_bus_card.dart`).
- Widget tests build their own plain `MaterialApp` (not the app theme) and assert exact values. Changing these requires updating tests:
  - corridor tab icon is a `Container` with `constraints: maxWidth == 40` inside `CorridorIconButton` (shared home/map); unselected color = `corridorColor('K1').withOpacity(0.35)`.
  - outside-hours purple `Color(0xFF7B1FA2)`.
  - icons `Icons.close`, `Icons.my_location`, `Icons.arrow_downward`.
  - `FloatingPinnedBusCard.contentKey`; expanded card height `< 240` (includes `PinnedBusCardFooter`), collapsed `< 120`; `DraggableScrollableSheet` 0.5/1.0/min<0.5; settings has exactly one `SwitchListTile`.
  - The pinned card's arrival line only appears when `UserArrival` is passed; the overlay tests default the user to the bus position (→ "sudah dekat"), so pass `userLocation:` to `_app` to get an ETA chip.
- Every new UI string must be added to **both** ARB files or `flutter gen-l10n` / the app breaks.
